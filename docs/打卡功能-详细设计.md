**日期**：2026-11-18　｜　**模块**：OA 一期 F1　｜　**状态**：设计定稿，前端先行（后端服务待建）

## 一、功能范围

员工在电脑端打开打卡页，完成上班卡 / 下班卡：拍照（可预览）＋ 定位展示 ＋ 一键提交。系统按规则判定正常/迟到/早退，结果回写并展示在「今日打卡」里。管理层可在后台配置打卡规则（时间窗口、适用人群、打卡方式），本期前端先用固定规则展示，规则配置项后续接入。

**本期交付**：前端页面 + 完整交互（真实调摄像头/定位，接口用模拟数据）；接口契约 + 数据结构定稿；后端服务下一阶段按此契约实现。

## 二、数据结构（MongoDB）

数据库 `openim_v3`，集合 `oa_checkin`。所有 OA 集合带 `company_id`（多租户铁律）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | ObjectId | 主键 |
| `company_id` | string | 公司标识，联合索引首列 |
| `user_id` | string | 关联 IM 用户 |
| `date` | string | 归属日期 `YYYY-MM-DD`，服务端生成 |
| `type` | string | `on`（上班卡）/ `off`（下班卡） |
| `checkin_time` | number | 服务端毫秒时间戳，**不信任客户端** |
| `photo_url` | string | MinIO 照片地址 `checkin/{userID}/{date}-{type}.jpg` |
| `location` | object | `{ lat, lng, name, in_fence }`，可选，按规则 |
| `device_info` | object | `{ model, ip, ua }`，辅助防代打 |
| `status` | string | `normal` / `late` / `early` / `makeup` |
| `rule_snapshot_id` | string | 打卡时生效的规则快照，保证历史可追溯 |
| `created_at` | number | 写入时间 |

**索引**：
```
(company_id, date, user_id)        常规查询
(company_id, user_id, date, type)  唯一，防重复打卡
```

**照片存储**：MinIO 桶 `oa`，路径 `checkin/{userID}/{date}-{type}.jpg`，加水印（时间＋姓名＋定位）在上传前由前端绘制到图片上。

## 三、接口契约

统一前缀 `/oa/api/v1/`，鉴权头 `token`（IM chatToken），`company_id` 由服务端从登录态注入，前端不传。响应统一 `{ code, msg, data }`。

### 3.1 提交打卡
```
POST /oa/api/v1/checkin/submit
```
请求：
```json
{
  "type": "on",
  "photo": "<base64 jpg>",
  "lat": 22.5431,
  "lng": 114.0579,
  "device_info": { "model": "Chrome", "ua": "..." }
}
```
响应：
```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "checkin_id": "...",
    "checkin_time": 1763463720000,
    "date": "2026-11-18",
    "type": "on",
    "status": "normal",
    "status_text": "正常",
    "lat": 22.5431,
    "lng": 114.0579,
    "address": "（配了地图 key 才有街道地址）",
    "distance": 59,
    "in_fence": true,
    "fence_set": true
  }
}
```

### 3.2 今日打卡状态
```
GET /oa/api/v1/checkin/today
```
响应：
```json
{
  "code": 0,
  "data": {
    "date": "2026-11-18",
    "on":  { "time": 1763463720000, "status": "normal", "photo_url": "..." },
    "off": null,
    "can_checkin": true,
    "rule": { "on_start": "07:00", "on_end": "09:30", "need_photo": true, "need_location": true }

}
```

### 3.3 打卡历史
```
GET /oa/api/v1/checkin/list?month=2026-11&page=1&page_size=30
```
响应：
```json
{
  "code": 0,
  "data": {
    "total": 12,
    "list": [
      { "date": "2026-11-18", "on": "09:02", "off": null, "status": "normal", "status_text": "正常" }
    ]
  }

```

## 四、判定规则（服务端）

1. 时间以服务端为准，客户端传的时间戳仅作参考不采信。
2. 上班卡：在 `[on_start, on_end]` 窗口内为正常，晚于 `on_end` 为迟到，窗口外（过早）记异常。
3. 下班卡：早于 `off_start` 为早退。
4. 定位：若规则要求且 `in_fence=false`，记「地点异常」。
5. 重复提交同一天同一类型：唯一索引拦截，返回「今日已打卡」。
6. 判定结果和规则快照一并入库，历史不受规则变更影响。

路由：`/checkin`，从工作台「拍照打卡」入口进入（待接入）。

**布局**（宽屏）：

## 七、关键风险

1. **HTTPS**：摄像头/定位在非安全上下文不可用；`localhost` 例外。局域网/公网访问必须 HTTPS（现有隧道已满足）。
2. **定位精度**：浏览器 GPS 是 WGS-84，打卡点坐标按 GCJ-02（腾讯/高德）配，两者在国内有 50~500 米偏差，
   半径别设太小（默认 500 米）；只做距离判定、不渲染地图。
3. **防代打**：一期靠「服务端时间＋定位围栏＋照片水印」，不做人脸识别。

## 八、定位与打卡点配置（2026-11-19 实现）

### 8.1 位置怎么来

| 环节 | 实现 |
| --- | --- |
| 取坐标 | 页面加载时 `navigator.geolocation.getCurrentPosition({ enableHighAccuracy: true })`，失败给出「权限被拒 / 无信号 / 超时」三档原因 + 「重新定位」 |
| 换地址、算距离 | `GET /oa/api/v1/checkin/locate?lat=&lng=`，服务端返回 `{ address, distance, in_fence, fence_set, office }` |
| 提交 | `POST /checkin/submit` 只传 `lat/lng`，服务端**重算**距离与范围，前端传什么都不能绕过 |
| 展示 | 打卡页显示真实经纬度 + 距打卡点距离 + 范围内/外标签；今日打卡与本月记录显示地址（有坐标兜底） |

不再有任何写死的位置文案：旧的「深圳总部 · 腾讯大厦 / 定位正常」已删除；旧的演示打卡记录（带假公司名、无坐标）也已清理。

### 8.2 打卡点（可选）

默认**不预设**任何公司地址：没配打卡点时 `fence_set=false`，只记录员工真实坐标，不判范围、也不显示公司名。
要启用考勤范围，在 `.env` 填以下几项后 `docker compose up -d --force-recreate xinbo-oa`：

| 变量 | 说明 |
| --- | --- |
| `XINBO_OA_OFFICE_LAT` / `XINBO_OA_OFFICE_LNG` | 打卡点坐标，GCJ-02；可在 https://lbs.qq.com/getPoint/ 拾取 |
| `XINBO_OA_OFFICE_NAME` | 展示用名称，留空则前端显示「当前位置」 |
| `XINBO_OA_OFFICE_ADDRESS` | 展示用地址 |
| `XINBO_OA_OFFICE_RADIUS` | 允许半径（米），默认 500 |
| `XINBO_OA_STRICT_FENCE` | `true` 超出半径直接拒卡；默认 `false` 照常打卡但记录标注「范围外 2.0 公里」 |
| `XINBO_OA_MAP_KEY` | 腾讯位置服务 key，仅服务端用于逆地理编码；留空则只显示坐标（不编造地址） |

### 8.3 拍照

- 前端已移除「用模拟照片」，摄像头不可用只提示授权/改手机；
- 后端在 `need_photo=true` 时拒绝空照片（`请先拍摄打卡照片`），且必须有坐标（`未获取到定位…`）；
- 照片落 MinIO `xinbo-oa` 桶，记录只存 `file_id`，查看时换 30 分钟签名地址。

### 9.1 出勤页布局

| 元素 | 规则 |
| --- | --- |

### 9.2 底部被裁的根因（已修）

`.checkin-page` 是 flex 纵向容器，`.checkin-body` 用了 `flex:1 1 auto` 但没写 `min-height:0`，
flex 子项默认 `min-height:auto` 会被内容撑高（实测 905px > 可视 804px），外层又是 `overflow:hidden`，
于是最后一屏内容被裁掉且滚不到。两处修复：`.checkin-body` / `.att-body` 都加 `min-height:0`，
并留 40px 底部 padding。

## 十、团队出勤与出勤报表（2026-11-19 实现）

> 起因：出勤只有「本人」视角，组长看不到组员。规划见 `docs/出勤团队视角-规划.md`，本节记录落地后的实际形态。

### 10.1 作息规则（本次改动的起点）

原来时段写死在代码里（07:00 / 09:30 / 18:00），本次改为配置：

| 环境变量 | 默认值 | 含义 |
|---|---|---|
| `XINBO_OA_WORK_ON_TIME` | `09:05` | 上班时间，晚于它打上班卡算迟到 |
| `XINBO_OA_WORK_OFF_TIME` | `18:00` | 下班时间，早于它打下班卡算早退 |
| `XINBO_OA_LATE_GRACE_MIN` | `0` | 迟到宽限分钟数 |
| `XINBO_OA_WORK_EARLIEST_ON` | `06:30` | 最早可打上班卡（防凌晨误触） |

判定统一用「当天第几分钟」比较（`parseHM` + `minuteOfDay`），不再 hour/minute 分开写。
规则随 `/checkin/today`、`/checkin/list` 下发，前端在出勤页顶部常显「工作时间 09:05 上班 · 18:00 下班」，
避免出现"页面写 9:00、后端按 9:30 算"。

### 10.2 权限：一份 `visibleUserIDs`，四个模块共用

```
visibleUserIDs(ctx, uid, scope)
  mine  → [uid]
  team  → 沿 manager_id 递归全部下属（一次查全公司通讯录在内存展开，visited 防环，排除 disabled）
  all   → 全公司（HR / 管理员）
```

- 放在 `internal/api/scope.go`，日报、考勤、后续待办/审批都调用它；`teamIDs` 改为 `visibleUserIDs(team)`，
  顺带修掉「只展开两层、四级组织断链」。
- 越权一律返回 `code=403`，**不回空列表**——空列表会被误读成"我组里没人"。
- `/me` 新增 `subordinate_count / can_view_team / can_view_all`（`bson:"-"` 计算字段，不落库），
  前端据此决定是否显示「团队出勤 / 出勤报表」，不自己按角色 if。

### 10.3 接口

| 接口 | 说明 |
|---|---|
| `GET /checkin/team?month=&date=&scope=&only_exception=` | 团队考勤：成员今日上下班 + 本月统计，异常优先排序 |
| `GET /checkin/team/:user_id?month=` | 某成员月历（只读）；不在汇报链 → 403，停用 → 非管理员 403 |
| `GET /checkin/report?month=&scope=&format=csv` | 出勤报表：一人一行 + 合计行；`format=csv` 直接下载 |

统计口径（`monthStatOf`，唯一实现）：

- **应出勤 = 已过完的工作日 + 今天（前提是今天已打上班卡）**。今天还没打卡就不进分母，
  否则早上七点打开报表人人都是「0/13」；今天已经来了就算应出勤，报表和团队表才对得上。
- **今天只打了上班卡 → `in_progress`（进行中）**，不算缺卡、不算单卡。这条同时修了本人月历的历史问题。
- **缺卡 = 无上班卡且该工作日已过完**；单卡 = 有上班卡无下班卡且已过完。
- **迟到/早退按记录如实计数，含今天**：16:11 打的卡就是迟到，这个事实不会因为今天还没下班而改变。
  否则会出现团队表写「迟到 1」、报表写「迟到 0」的情况，没人会信这张表。
- 出勤率 = 实际出勤 / 应出勤，四舍五入到百分比；实际出勤恒 ≤ 应出勤。
- 平均上下班只统计真实记录，缺卡不参与平均（否则会被当成 00:00 拉飞）。

### 10.4 页面

出勤页顶部三档：`我的出勤 / 团队出勤 / 出勤报表`（后两档由 `can_view_team` 控制）。

- 团队出勤：`应到 N 人 · 已打卡 N · 未打卡 N · 迟到 N · 早退 N` + 「只看异常」开关；
  表格一行一人，姓名后橙点标今日异常；异常行底色浅橙；点「查看月历 →」开抽屉看只读月历。
- 出勤报表：表格 + 合计行 + 「导出报表」；导出走带 token 的 blob 请求（`window.open` 带不了 header），
  服务端写 UTF-8 BOM，Excel 直接打开不乱码，文件末尾附统计口径说明。
- 领导/HR 多一档 `我的团队 / 全公司` 切换。
- 两个视图都常显一句「缺卡按当天没有打卡记录计算，暂未接入请假/出差，请勿据此直接做处罚判断」。

### 10.7 两个前端缺陷（2026-11-19 修复）

**① 视图切换「选中了却看不出来」**

现象：`我的出勤 / 团队出勤 / 出勤报表` 三档都是灰字，分不清当前在哪一档，后两档还像是禁用的。

原因：antd `Segmented` 的选中项是**白底 + 淡阴影**，而它坐在白色工具栏上，白底叠白底，选中态等于没有；
未选中项又是灰字，视觉上整体退化成"三个灰标签"。

修法：新增 `.view-switch`（`attendance/index.module.scss`），选中项改为实心蓝 `#0b5fd8` + 白字 + 轻投影，
未选中 `#4a5a75` 并在 hover 时变蓝、加淡蓝底，明确"这是可点的"。三处复用：
顶部三档视图、团队出勤与出勤报表里的「我的团队 / 全公司」。small 尺寸单独收窄左右留白（10px），避免文字顶到蓝块边缘。

**② 团队出勤 / 出勤报表「一直在转圈」**

现象：表格数据其实已经拿到，但被 Spin 蒙层盖住整体发灰，加载圈不消失；后端接口被持续重复调用。

根因是**依赖链引发的无限重渲染**，不是接口慢：

```
父组件 onError={(m) => message.error(m)}   // 每次渲染都是新函数
  → 子组件 load 的 useCallback 依赖 [.., onError] 每次都变
  → useEffect(() => { load() }, [load]) 每次渲染都触发
  → setLoading(true) → 请求 → setData → 重渲染 → 再请求 …
```

修法（两处都改，双保险）：

1. 子组件（`TeamView` / `ReportView`）把 `onError` / `onRule` 放进 `useRef`，`load` 的依赖只留真正影响请求的参数
   （`month` / `scope` / `onlyException`）；
2. 父组件用 `useCallback` 固定 `handleError`，不再传内联箭头函数；
3. 顺手加 `reqId`：快速切月/切范围时只认最后一次响应，避免旧数据回来后覆盖新数据。

验证：进入视图后 8 秒内 `/checkin/team`、`/checkin/report` 各只请求 **1 次**（修复前是持续循环），
`.ant-spin-spinning` 数量为 0，表格容器 `opacity: 1`。

> 教训：`useEffect` 依赖里放父组件传来的回调，必须先确认引用稳定；能用 ref 存回调就不要进依赖数组。

## 十一、请假与补卡（2026-11-19 实现，批次 4）

> 开工前按用户新要求做了全局性评审（8 条清单），答案见 `docs/OA剩余开发清单与排期.md` 批次 4 设计明细。
> 核心决定：**请假不写打卡表**（请假日不是打了卡，只影响统计口径），**补卡写打卡表**（补的是真实上班/下班事实，source=makeup）。

### 11.1 数据表（申请即落库、审批只改状态）

- `oa_leave`：`leave_id / user_id / type / start_date / end_date / days（工作日）/ reason / status / approver_id / comment / approved_at`。索引 `(company_id,user_id,status)` 和 `(company_id,start_date,end_date)`。
- `oa_makeup`：`makeup_id / user_id / date / type(on|off) / time / reason / status / approver_id / checkin_id`。唯一索引 `(company_id,user_id,date,type,status)` 防重复有效申请。
- `oa_checkin` 新增 `source`（normal / makeup）与 `makeup_id`，打卡唯一索引不变。

### 11.2 权限：审批人按汇报链定，不按角色 if

- 提交时把申请人的 `manager_id` 写进 `approver_id`（关系驱动，前端传什么都改不了）；无上级时由领导/HR 审批。
- 审批校验 `canApproveRequest`：必须是该申请指定的审批人，或 HR/管理员（仅无上级时）；**不能自批自**。
- 列表三档 `mine / team / all` 复用 `visibleUserIDs`，越权 403 不回空列表。
- 工作台待办「N 条请假/补卡待审批」也走同一套可见范围，组长看直属、领导看整条链。

### 11.3 状态机与边界

```
pending ──approve──→ approved（补卡同时生成 checkin）
   │
   ├──reject───→ rejected
   └──cancel──→ cancelled（仅本人、仅 pending）
```
- 处理后锁定，重复审批返回"该申请已处理"。
- 请假：只算工作日天数（周末不计），单次上限 120 个工作日；已批准的工作日不算缺卡、不计入应出勤分母。
- 补卡：只补过去 7 天（`OA_MAKEUP_MAX_DAYS`）、每月最多 3 次（`OA_MAKEUP_MAX_MONTH`），同一天同一类型已有卡或已有有效申请一律拒绝；审批通过瞬间再查一次卡，防止"待批期间又现场打了卡"。
- 补卡仍按作息判迟到/早退：09:30 补上班卡就是迟到，不因为是"补的"就放过。

### 11.4 统计口径合并（`monthStatOf` 唯一实现）

新增 `leaveDays` 入参：请假日整段跳过（不算出勤/缺卡/应出勤），`stat.Leave++`。
团队表、出勤报表、CSV 都走这一个函数，数字完全一致：
- 报表与 CSV 新增「请假(天)」列，合计行累加；
- `warnings` 从 `leave_not_integrated` 改为 `holiday_calendar_not_integrated`（节假日日历未接入，工作日只按周一至周五判），前端提示同步更新。

### 11.5 页面

新增 `请假与补卡` 页（`#/leave`，工作台入口）：
- 我的申请 / 待我审批 / 已处理 三档；领导/HR 多「我的团队 / 全公司」切换；
- 申请弹窗（请假：类型+起止+事由；补卡：日期+类型+时间+原因）；
- 审批弹窗强制填意见，同意/拒绝即时生效；本人可撤销 pending 申请；
- 视图切换沿用出勤页的蓝底白字高亮，避免白底叠白底。
