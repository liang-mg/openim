# 宝塔面板部署（域名版）— im.9yy.asia

> 适用：已装宝塔面板的 Linux 服务器（推荐 Ubuntu 22.04 / CentOS 7+），域名 `im.9yy.asia` 已解析到本机公网 IP。
> 目标：浏览器打开 `https://im.9yy.asia` 即可用「新博」OA 系统。

## 核心思路

项目自带一套 Docker Compose 编排 + 一个**内置 nginx 的 `oa-web` 容器**（宿主机只暴露 5173），所有后端路径（`/api` `/chat` `/oa` `/msg_gateway` `/oss`）都已在这个 nginx 里配好反代。所以宝塔这边**只做两件事**：

1. 用宝塔装 Docker、放行端口、跑起项目（构建镜像 + 启动服务）
2. 用宝塔建站点 + 申请 SSL 证书 + 把整个站点反代到 `127.0.0.1:5173`

不需要在宝塔里逐条配 `/oa`、`/api` 的反代——那是 `oa-web` 容器内部的事，已经做好了。

---

## 第一步：宝塔面板准备（网页操作）

### 1.1 安装 Docker
- 宝塔左侧菜单 → **软件商店** → 搜索「Docker」→ 安装官方 Docker 管理器（或直接装 Docker CE）
- 装完后确认 Docker 正常：宝塔终端（左侧「终端」）执行 `docker -v` 能看到版本号

### 1.2 放行端口
两三处都要放行 **80、443**：
- 宝塔 → **安全** → 放行端口：80、443（若 5173 也想直接访问可加，但域名版不必对外开放）
- 云服务器厂商控制台 → 安全组/防火墙 → 放行 80、443（**这步在网页后台，宝塔管不到**）

### 1.3 确认域名解析
- 域名服务商后台确认 `im.9yy.asia` 的 A 记录已指向本机公网 IP，`ping im.9yy.asia` 能解析到该 IP

---

## 第二步：拉取代码并启动服务（宝塔终端）

左侧菜单 → **终端**，以下命令都在服务器命令行执行：

```bash
# 找一个好的放置目录（宝塔默认 www 目录）
cd /www/wwwroot

# 克隆仓库
git clone https://github.com/liang-mg/openim.git
cd openim
```

### 2.1 修改配置 .env
```bash
cp config-template/oa.env.example .env
vi .env
```
找到并修改（或用宝塔文件管理器双击编辑 `.env` 更直观）：

```ini
LIVEKIT_URL=wss://im.9yy.asia:7880
MINIO_EXTERNAL_ADDRESS="https://im.9yy.asia/oss"
OPENIM_SECRET=<填一个强随机字符串，如 Xinbo@2026，IM 服务间共享用>
XINBO_OA_TOKEN_SECRET=chat123
OA_MAP_KEY=<你的地图 key，打卡定位用，没有可留空>
```

> ⚠️ **注意：这两个 secret 不是一回事，不要填成一样！**
> - `OPENIM_SECRET`：IM 服务间共享密钥（server 与 chat 之间），可自定义任意强随机串。
> - `XINBO_OA_TOKEN_SECRET`：**必须填 `chat123`**——这是官方 chat 镜像内置 `config/chat-rpc-admin.yml` 里的固定 secret，登录用的 chatToken 由它签发，OA 后端靠它校验。填错会导致全站 401、登录失败。
>
> 这是本项目域名部署的**头号坑**：很多人误以为两个 secret 要一致，其实管登录的是 `chat123`，和 `OPENIM_SECRET` 无关。若官方 chat 镜像升级后改了这个内置值，登录会失效，届时以镜像内 `chat-rpc-admin.yml` 的 secret 为准。

### 2.2 一键部署
```bash
bash deploy/deploy.sh bootstrap
```
看到 `OA 环境已就绪` 即成功。这会构建后端+前端镜像、启动底座（mongo/minio/redis/etcd/kafka）与 IM 服务（openim-server/openim-chat），再起三个 OA 服务：后端 10010、OA 网页 5173、管理后台 11002（新博品牌）。

> ⚠️ `openim-server` 官方镜像约 640MB，首次拉取较慢，**务必保持终端连接直到命令返回**，中途断开会导致镜像没拉全、容器没创建，进而让 oa-web 反复重启、页面打不开。万一中断了，重新执行 `bash deploy/deploy.sh up` 即可续上（已下载的镜像层会复用）。`openim-server` 有约 5 分钟健康检查观察期，`openim-chat` 随后自动就绪。

验证网页容器活着：
```bash
curl -I http://127.0.0.1:5173    # 应返回 200
```

## 第三步：宝塔建站点 + SSL 证书（网页操作）

### 3.1 建站点
- 宝塔左侧 → **网站** → **添加站点**
- 域名填 `im.9yy.asia`
- 根目录随便（如 `/www/wwwroot/im.9yy.asia`），**不用上传任何文件**
- PHP 版本选「纯静态」
- 确定

### 3.2 申请 SSL 证书
- 站点列表点 `im.9yy.asia` → **SSL** → **Let's Encrypt** → 申请证书
- 申请成功后，开启 **强制 HTTPS**
- （可选）开启 **HSTS**：先别急着开，确认 HTTPS 稳定后再开

### 3.3 配置反向代理（关键）
- 站点设置 → **反向代理** → **添加反向代理**
- 代理名称：随便（如 `oa`）
- 目标 URL：`http://127.0.0.1:5173`
- 发送域名：`$host`（默认即是）
- **开启 WebSocket**：✅ 必须开（消息网关 `/msg_gateway`、LiveKit `/livekit` 都走 WS，不开会导致消息收不到、通话信令断了）

添加后，宝塔会生成一份反代配置。点「配置文件」确认关键项，缺的补上：

```nginx
# 在 location / 里，确保有这些（宝塔一般会自动生成）
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_read_timeout 3600s;
client_max_body_size 100m;
```

> ⚠️ **两个必查项**：
> 1. `client_max_body_size 100m` — 打卡照片/附件上传，太小会 413
> 2. `proxy_read_timeout 3600s` — 消息网关长连接，默认 60s 会断线

## 第四步：验证

浏览器打开 `https://im.9yy.asia`：
- 能看到「新博」登录页 → ✅ 前端 + SSL 正常
- 用测试账号登录（如 `12345678001` / `Xinbo@2026`）→ ✅ 后端 + 鉴权正常
- 发条消息、上传张图片 → ✅ 反代 WebSocket + 大文件配置正常

命令行冒烟（任选一台能联网的机器）：
```bash
curl -I https://im.9yy.asia                       # 200
curl https://im.9yy.asia/oa/api/v1/healthz        # OA 后端健康
```
服务器内跑完整校验：`cd /www/wwwroot/openim && bash deploy/deploy.sh verify`

## 必读提醒

1. **HTTPS 是刚需**：非 HTTPS 下浏览器禁用摄像头和定位，打卡功能不可用。域名 + SSL 正好解决。
2. **secret 对齐**：`XINBO_OA_TOKEN_SECRET` 必须填 `chat123`（官方 chat 镜像内置 secret），填错全站 401；`OPENIM_SECRET` 可自定义，两者不需要一致。
3. **音视频通话**：WebRTC 走 UDP，宝塔反代只转 HTTP/WS。要真实通话需在云服务器安全组放行 **UDP 7882**（或配 TURN）。信令（来电弹窗、接听）不受影响。
4. **证书续期**：宝塔的 Let's Encrypt 一般会自动续期；若没有，加个计划任务每月执行 `certbot renew`。
5. **桌面端 exe**：内置服务器地址目前写死 `127.0.0.1`（`frontend/src/utils/serverConfig.ts` 的 `BUILTIN_SERVER_HOST`），要给同事用桌面端，得改成 `im.9yy.asia` 后重新 `build:win`。网页版不受影响。
6. **不要对外开放 10010/5173**：域名版只需 80/443，其余端口留在服务器内网即可，减少攻击面。

## 附：另一种做法（不用宝塔反代）

项目也自带 `deploy/docker-compose.oa.tls.yaml`，可在服务器内直接起一个 TLS 反代容器（80 跳 443、自动反代 5173）。但那样证书要手动放到指定目录、且 80/443 会被这个容器占用，**和宝塔建站冲突**。既然用了宝塔，推荐就用上面的「建站 + SSL + 反代」方式，证书续期交给我们熟悉的宝塔面板。
