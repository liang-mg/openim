# PC端开发计划1120

本轮补齐员工在桌面浏览器里打卡、请假、补卡和写日报的流程，让组长能处理待办，领导能看团队情况，HR/管理员能维护组织和规则。现有 React 网页、Go 接口、MongoDB 和 MinIO 继续使用。

**范围。** PC 端指桌面浏览器里的 OA 网页，保留现有拍照、定位和提交打卡。P3-5 移出本计划。手机端专项适配、原生桌面客户端、Electron 和 App 属于其他项目范围。

**核对基线。** `dev1120` 的固定提交 `11e6736`。以该提交的前端入口、后端接口和数据处理为准。核对时工作区里的 `.gitignore`、`deploy/deploy.sh`、`frontend/Dockerfile` 未提交修改未计入成果。需求来自 [OA 剩余开发清单与排期](./OA剩余开发清单与排期.md)，其中批次 5、6 的“已完成”包含仍需补齐的验收项。

**授权边界。** 本文件是开发计划。构建发布、备份恢复和 HTTPS 的交付物在测试环境演练。实际生产发布、域名配置和生产数据操作按届时单独授权执行。

## 发布门槛 · P3-6 HTTPS 与各角色回归

- **HTTPS。** 现有 Nginx 监听 HTTP 80 并反代 OA，文档有临时 HTTPS 隧道与自有域名配置说明。确认目标域名与证书部署位置后，交付测试环境 TLS 配置、续期和回滚步骤。验收使用有效证书访问测试站，验证 HTTP 跳转、同源接口和静态资源，允许相机及定位后完成实际打卡。见 [Nginx 配置](../frontend/nginx/site.conf)和[内网穿透指南](./内网穿透自助指南.md)。
- **四类账号。** 员工验收打卡、请假附件、异常申诉和个人通知。组长验收直属员工审批、查看本组出勤以及提交自己的日报。领导验收直属组长的日报、团队统计与催交。HR/管理员验收组织、规则、日志、公告和合同。使用两条独立汇报链，复查已有文件鉴权（P0-1）、补卡审批后入账（P1-3）和团队出勤跨组隔离（3.2），检查自审及停用账号的边界。
- **兼容与失败情况。** 用没有规则快照及附件的历史记录、原部门文本数据和已归档日报验证升级前后可读性。用同日重复扫描、并行催交及 Webhook 失败验证不会重复写入、不会显示错误的送达结果。
- **验证记录。** 每批记录实际命令、关键页面、接口结果和待补验收项。最终运行适用的后端测试和前端构建，在隔离测试环境完成浏览器回归、备份恢复和发布回滚。产品功能验收和环境演练各自给出结果。
