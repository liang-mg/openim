## 三、权限怎么分

### 3.1 三级角色

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 员工 | 拍照打卡、写/改/撤回自己的日报、看自己的打卡记录和上级点评 | 看别人的日报、点评任何人、进入查阅页（会提示"仅组长与领导可用"） |
| 组长 | 看**自己组员**提交的日报、写点评、点评后上报领导 | 看别的组、看已上报领导的报告、归档（会报"无权归档该报告"） |
| 领导 | 看**本团队**待审 + 已归档的全部日报、点评并归档 | 越过汇报链看其它团队 |

### 3.2 隔离靠什么实现

两层校验，都在**服务端**，前端传什么都不作数：

1. **身份**：从 IM 的 chatToken 解析出 user_id，再查 `oa_employee` 拿角色和上级；前端不传 userID。
2. **范围**：统一走 `visibleUserIDs(ctx, uid, scope)`，按 `manager_id` 递归汇报链、防环、排除停用。
3. **停用**：账号被停用后，即使仍持有旧 token，访问 OA 接口也立即返回 `code=403, 账号已停用，请联系管理员`（2026-11-20 补）。
4. **多租户**：所有查询强制带 `company_id=xinbo`，跨公司拿不到数据。

### 3.3 日报状态机

```
草稿 draft
  ↓ 提交
待组长查阅 submitted  ←─ 2 小时内可撤回
  ↓ 组长点评 + 上报
待领导查阅 pending_leader   ← 员工不可再改（"已上报领导，不可修改"）
  ↓ 领导点评 + 归档
已归档 archived        ← 永久锁定（"该日报已归档，不可修改"）
```

> 已归档和已上报两种状态的覆盖写，后端会直接拒绝，防止归档内容被员工改掉。

## 六、已知限制（别踩）

1. **只有 dev 服务有 OA 页面**。走 `npx vite --config vite.web.config.ts` 启动的 5173；`11001` 上的旧静态包没有 OA 页面。
2. **账号由 IM 管，OA 不存密码**。OA「员工与权限」只能给**已存在的 IM 账号**建档；要新建 IM 账号，去 OpenIM 管理后台 `11002` 或走注册接口，再来 OA 建档。
3. **`Xinbo@2026` 是测试密码**，六个账号共用，上线前必须逐个改掉。
4. **其它手机号也能登录 IM，但默认没有 OA 档案**，会按"普通员工 + 未分配部门"兜底，提交的日报没有组长能看到。用管理员在「员工与权限」里添加并指定上级即可。
5. HR 角色（`hr`/`admin`）代码里已预留，暂无测试账号。它的权限介于组长和领导之间：能看全团队、能归档，但不需要汇报链关系。

## 七、给管理员：怎么加人、调角色、设直属关系

管理员在 OA 左侧导航点「**管理**」，进入「员工与权限」页即可，**不用改代码、不用重启服务**。

### 7.1 谁是管理员

| 姓名 | 手机号 | 业务角色 | 管理员 |
|---|---|---|---|
| 王经理 | 19306860353 | 领导 | 是（默认） |

「管理员」和业务角色是两个独立的勾选项：管理员决定**能不能维护人员**，业务角色决定**能看哪些日报**。所以领导可以兼任管理员。

### 7.2 添加一个员工

1. 先在 OpenIM 后台 `11002` 注册 IM 账号（手机号 + 密码）
2. 回到 OA「员工与权限」点右上「**添加员工**」
3. **IM 账号**：下拉里只列已注册、还没建 OA 档案的账号，可搜昵称或手机号
4. 选完账号，**姓名**自动带入昵称，可改；填**部门**（必填）
5. **岗位**可不填，如「前端工程师」
6. **角色**三选一：员工 / 组长 / 领导
7. **直属上级**：下拉只出现组长和领导；留空表示顶层
8. **管理员**：默认关，需要给人事权限时打开
9. 点「保存」，该成员立刻可以用自己的账号密码登录并使用 OA

### 7.3 调整角色与直属关系

在列表里点对应成员的「**编辑**」，改完保存即时生效。常见场景：

- **提拔组长**：编辑该员工 → 角色改「组长」→ 保存。他立刻能在「查阅」里看到自己组员的日报。
- **换组长/调部门**：编辑组员 → 直属上级改选另一个人 → 保存。日报随之流转到新组长。
- **加一个领导**：编辑 → 角色改「领导」→ 上级留空或选上级领导。

### 7.4 停用（离职）

点该成员右侧「**停用**」，确认即可。规则：

- 停用后立即断掉 OA 访问，**旧 token 也失效**（不必等 token 过期）
- 不再出现在任何人的汇报链里，也不再收到待办
- **历史全部保留**：已提交的日报、打卡记录、点评都在
- 默认列表看不到停用的人，勾选右上「含已停用」可查看并「启用」
- 两个保护：**不能停用自己**；**有在岗下属时不能停用**（要先把他下属的直属上级转走）

### 7.5 系统会拦下的错误操作

| 操作 | 提示 |
|---|---|
| 直属上级选成自己 | 直属上级不能是自己 |
| 把 A 的上级设成 B，而 B 的上级又是 A | 直属关系会形成环，请检查上级链 |
| 姓名 / 部门留空 | 姓名不能为空 / 部门不能为空 |
| 停用还有下属的组长 | 该成员还有 N 名在岗下属，请先转移下属的直属上级 |
| 取消最后一个管理员 | 至少保留一个管理员，不能取消自己的管理员权限 |
| 非管理员直接调接口 | 无权管理员工 |

### 7.6 和 OpenIM 后台的分工

| 在哪管 | 管什么 |
|---|---|
| OpenIM 管理后台 `http://127.0.0.1:11002` | 注册账号、改密码、封禁、改昵称、群组 |
| OA「员工与权限」页 | 部门、岗位、角色、直属上级、管理员标记、停用 |

OpenIM 本身没有部门、岗位、汇报关系这些字段，所以组织关系必须在 OA 里维护；反过来 OA 不保存密码，账号密码只认 IM 那一份，避免两套账号体系打架。
