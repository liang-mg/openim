## 三、权限怎么分

### 3.1 三级角色

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 员工 | 拍照打卡、写/改/撤回自己的日报、看自己的打卡记录和上级点评 | 看别人的日报、点评任何人、进入查阅页（会提示"仅组长与领导可用"） |
| 组长 | 看**自己组员**提交的日报、写点评、点评后上报领导 | 看别的组、看已上报领导的报告、归档（会报"无权归档该报告"） |
| 领导 | 看**本团队**待审 + 已归档的全部日报、点评并归档 | 越过汇报链看其它团队 |

### 3.2 隔离靠什么实现

两层校验，都在**服务端**，前端传什么都不作数：

1. **身份**：从 IM 的 chatToken 解析出 user_id，再查 `oa_employee` 拿角色和上级；前端不传 userID。
2. **范围**：组长的可见范围 = `manager_id` 指向自己的人；领导的可见范围 = 下属 + 下属的下属（`teamIDs`）。
3. **多租户**：所有查询强制带 `company_id=xinbo`，跨公司拿不到数据。

### 3.3 日报状态机

```
草稿 draft
  ↓ 提交
待组长查阅 submitted  ←─ 2 小时内可撤回
  ↓ 组长点评 + 上报
待领导查阅 pending_leader   ← 员工不可再改（"已上报领导，不可修改"）
  ↓ 领导点评 + 归档
已归档 archived        ← 永久锁定（"该日报已归档，不可修改"）
```

> 已归档和已上报两种状态的覆盖写，后端会直接拒绝，防止归档内容被员工改掉。

## 六、已知限制（别踩）

1. **只有开发环境能用**。`http://127.0.0.1:11001` 上跑的是 11-13 的旧前端包，没有 OA 页面。
2. **其它手机号也能登录，但默认没有 OA 档案**（如 13900000001）。没有档案时系统会兜底按"普通员工 + 未分配部门"处理，他们提交的日报没有任何组长能看到。用管理员在「员工与权限」里添加并指定上级即可解决。
3. **附件和打卡照片还没真存**。附件用的是浏览器本地地址，刷新即失效；打卡照片后端写空。领导点"下载"会 404。
4. **验证码 666666 是开发环境固定值**，不是真实短信；上线要换成真实短信通道或账号密码。
5. HR 角色（`hr`/`admin`）代码里已预留，暂无测试账号。它的权限介于组长和领导之间：能看全团队、能归档，但不需要汇报链关系。

## 七、给管理员：怎么加人、调角色、设直属关系

管理员在 OA 左侧导航点「**管理**」，进入「员工与权限」页即可，**不用改代码、不用重启服务**。

### 7.1 谁是管理员

| 姓名 | 手机号 | 业务角色 | 管理员 |
|---|---|---|---|
| 王经理 | 19306860353 | 领导 | 是（默认） |

「管理员」和业务角色是两个独立的勾选项：管理员决定**能不能维护人员**，业务角色决定**能看哪些日报**。所以领导可以兼任管理员；以后要独立的 HR 账号，也只是新开一个人、勾上管理员、业务角色选员工。

### 7.2 添加一个员工

1. 点右上「**添加员工**」
2. **IM 账号**：下拉里只列已注册的 IM 账号，可以搜昵称或手机号；已建过档案的会标「已有档案」并置灰
3. 选完账号，**姓名**自动带入昵称，可改；填**部门**（必填）
4. **岗位**可不填，如「前端工程师」
5. **角色**三选一：员工 / 组长 / 领导
6. **直属上级**：下拉只出现组长和领导；留空表示顶层（例如公司负责人）
7. **管理员**：默认关，需要给人事权限时打开
8. 点「保存」，该成员立刻可以打卡、写日报

### 7.3 调整角色与直属关系

在列表里点对应成员的「**编辑**」，改完保存即时生效。常见场景：

- **提拔组长**：编辑该员工 → 角色改「组长」→ 保存。他立刻能在「查阅」里看到自己组员的日报。
- **换组长/调部门**：编辑组员 → 直属上级改选另一个人 → 保存。日报随之流转到新组长。
- **加一个领导**：编辑 → 角色改「领导」→ 上级留空或选上级领导。

### 7.4 停用（离职）

点该成员右侧「**停用**」，确认即可。规则：

- 停用后：登录看不到 OA 入口，不再出现在任何人的汇报链里
- **历史全部保留**：已提交的日报、组长和领导的点评、打卡记录都在
- 默认列表看不到停用的人，勾选右上「含已停用」可查看并「启用」
- 两个保护：**不能停用自己**；**有在岗下属时不能停用**（要先把他下属的直属上级转走，否则这些人的日报会没人能审）

### 7.5 系统会拦下的错误操作

| 操作 | 提示 |
|---|---|
| 直属上级选成自己 | 直属上级不能是自己 |
| 把 A 的上级设成 B，而 B 的上级又是 A | 直属关系会形成环，请检查上级链 |
| 姓名 / 部门留空 | 姓名不能为空 / 部门不能为空 |
| 停用还有下属的组长 | 该成员还有 N 名在岗下属，请先转移下属的直属上级 |
| 取消最后一个管理员 | 至少保留一个管理员，不能取消自己的管理员权限 |
| 非管理员直接调接口 | 无权管理员工 |

### 7.6 和 OpenIM 后台的分工

| 在哪管 | 管什么 |
|---|---|
| OpenIM 后台 `http://127.0.0.1:11002` | 注册账号、改昵称、改密码、封禁、群组 |
| OA「员工与权限」页 | 部门、岗位、角色、直属上级、管理员标记、停用 |

OpenIM 本身没有部门、岗位、汇报关系这些字段，所以组织关系必须在 OA 里维护。好处是**不用重复建账号**：加人时直接从 IM 已有账号里挑。
