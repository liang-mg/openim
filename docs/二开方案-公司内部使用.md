# 新搏（OpenIM）二次开发方案 —— 公司内部使用

> 基于当前部署（OpenIM Server v3.8.3-patch.18 / Chat v1.8.4-patch.5 / electron-enterprise web v3.8.3）
> 目标：内网私有化、员工用公司账号登录、有组织架构、可审计、可运维。

---

## 0. 先认清分层：改哪一层，代价完全不同

| 层 | 组件 | 源码 | 二开代价 | 建议 |
|---|---|---|---|---|
| ① UI 层 | `openim-web-front`（web 聊天） | github.com/openimsdk/**openim-electron-enterprise** | 低（React + Vite，改页面/文案/主题） | 主要改这里 |
| ② UI 层 | `openim-admin-front`（管理后台） | github.com/openimsdk/**openim-admin** | 低（Umi + antd） | 加组织架构/审计菜单 |
| ③ 业务层 | `openim-chat`（10008 业务 API / 10009 管理 API） | github.com/openimsdk/**chat**（本地 `src/chat`） | 中（Go + Gin，接口清晰） | SSO、注册管控、审计都放这 |
| ④ 核心 IM | `openim-server`（10001 WS / 10002 API） | github.com/openimsdk/**open-im-server**（本地 `src/open-im-server`） | **高**（gRPC 微服务 + Kafka/Etcd，升级极痛） | 尽量只用配置，不改代码 |
| ⑤ 基础设施 | Mongo / Redis / Kafka / MinIO / Etcd | — | — | 只调参、做备份 |

**关键判断**：90% 的公司内网需求（登录、组织、权限、水印、审计）都能在 ①②③ 完成，别碰 ④。
镜像 label 里已确认来源仓库（`docker inspect openim-web-front` → `openim-electron-enterprise`），
这是拿前端源码的准确出处——现在这套「往构建产物里替换字符串」的做法（`frontend-custom/`）
只适合改文案，做不了功能，正式二开必须换源码工程。

## 1. 第一阶段：0 代码，先把「能内部用」的坑填上（半天）

### 1.1 关掉开放注册（最紧急）
当前 `/account/register` 用的是 `mw.CheckAdminOrNil`，**不带 token 也放行 = 谁都能注册**。

```go
// src/chat/internal/api/chat/start.go:131
account.POST("/register", mw.CheckAdminOrNil, chat.RegisterUser)  // 改前
account.POST("/register", mw.CheckAdmin,       chat.RegisterUser)  // 改后：只有管理员能建号
```
语义见 `src/chat/internal/api/mw/mw.go:92`：`CheckAdminOrNil` 解析失败就 `return`，等于放行。

想让员工自己注册但要校验企业邮箱域，就在 `RegisterUser`（`internal/api/chat/`）里加域名白名单
`@yourcorp.com`，其余直接拒绝。

### 1.2 换掉默认密钥（`.env`）
```ini
OPENIM_SECRET=<CHANGE_ME_SECRET>      # ← 必须换，且和数据库密码分开，32 位随机
MONGO_PASSWORD=...
REDIS_PASSWORD=...
MINIO_SECRET_ACCESS_KEY=...
```
改完 `docker compose up -d` 重建；`OPENIM_SECRET` 一变，所有已发 token 立即失效（预期行为）。
token 有效期在 `src/open-im-server/deployments/templates/config.yaml:299` 的 `tokenPolicy.expire`。

### 1.3 消息留存（合规）
同一份 config 里有 `retainChatRecords`（默认按周清理 N 天前消息）。
公司内部一般要求留存 180 天以上，把值调大或设为 0（不清理），并同步做好 Mongo 备份。

### 1.4 内网运行的前提
- 全站 HTTPS + 内网域名（自签也要给客户端装根证书，否则 App/WebView 白屏）；
- **纯内网无外网**时，把前端里所有外链资源本地化：emoji 图、头像默认图、地图、字体、`wasm` 已在本地，主要是 emoji/贴图 CDN；
- MinIO 不要暴露公网，走 nginx `/oss/` 同源代理（现有 `site.conf` 已经是这个思路）。

### 1.5 备份（没有备份的内网系统等于没有系统）
```bash
# 每天 2:00
docker exec mongo mongodump --uri="mongodb://user:pass@127.0.0.1:27017/openim_v3" --archive | gzip > /backup/openim_$(date +%F).gz
docker run --rm -v openim-docker-latest_data:/data -v /backup:/out alpine tar czf /out/minio_$(date +%F).tgz /data
```
保留 14 天，异地一份。

## 2. 第二阶段：员工身份（SSO）——内部使用最核心的一步

### 2.1 目标
员工打开就是公司账号，不出现「注册」「忘记密码」「验证码」。

### 2.2 推荐做法：在 chat 服务加一个 SSO 登录接口

```
POST /account/login/sso   { ticket }  →  { token, userID, ... }
```

落点：`src/chat/internal/api/chat/start.go` 的 `account` 路由组下新增一行 +
`internal/api/chat/` 里新增 `login_sso.go`。逻辑：

1. 拿 `ticket` 去公司统一认证（企业微信/钉钉/LDAP/OAuth2/内部网关校验接口）换 `工号 + 姓名 + 邮箱 + 部门`；
2. 用 `openim-sdk-core` 的 `UserRegister`（或直接调 chat 内部 `user.Register`）按工号建用户，`userID = 工号`；
3. 调用已有的 `Login` 逻辑签发 OpenIM token（复用 `chat.Login` 里的 token 生成部分）；
4. 返回给前端，前端存 token 后照常进首页。

### 2.3 三种对接方式怎么选

| 公司现状 | 做法 | 工作量 |
|---|---|---|
| 有统一认证/门户（CAS/OAuth2/内部 JWT） | 前端跳到门户，回跳带 ticket，走 2.2 | 3~5 天 |
| 只有 AD/LDAP | chat 里加 `go-ldap` 绑定时校验 + 定时同步人员 | 5~8 天 |
| 企业微信/钉钉 | 用「企业内应用」拿 `userid`，走 2.2 同一接口 | 3~5 天 |

**过渡方案（1 天）**：先不接 SSO，用管理端批量导入账号（`/account/register` 带 admin token 批量调），
前端登录页把「注册」入口隐藏掉，员工用「工号 + 初始密码」登录，首登强制改密。

### 2.4 前端改动
`openim-electron-enterprise` 里登录页组件替换为：
一个「企业账号登录」按钮 → 跳转/回调拿 ticket → 调 `/account/login/sso`。
同时删掉：手机号/邮箱 tab、验证码登录、注册入口、忘记密码。

## 3. 第三阶段：组织架构（OpenIM 本身没有「部门」概念）

代码里搜不到任何 `department/organization`——这是必须自己补的部分。两条路：

### 路线 A：用「群」承载部门（0 开发，先跑起来）
- 每个部门建一个群，群名 = 部门名，群主 = 部门负责人，群公告 = 部门通知；
- 全员群 + 部门群 + 项目群，用「群标签」区分；
- 管理端已经有群管理，够用。
- 缺点：人员调动要手动拉群；通讯录还是「所有人可见」。

### 路线 B：自建组织架构服务（正式做法，2~3 周）
1. 新表（放 chat 的 Mongo 库或单独库）：`org_department(id, parent_id, name, sort)`、`org_member(user_id, dept_id, title)`；
2. chat 新增接口组：
   ```
   GET  /org/tree           部门树
   POST /org/member/list    按部门查人
   POST /org/member/move    调岗（同时同步群成员）
   ```
3. 管理端 `openim-admin` 加「组织架构」页（antd Tree + Table，两天能出原型）；
4. 与 IM 的衔接：`userID` 用工号；部门群成员变更时调 OpenIM 的 `InviteUserToGroup` / `KickGroupMember`；
5. 通讯录可见性：`/user/search/full`、`/friend/search` 加部门过滤（只允许搜本部门 + 上级部门 + 全员群成员），前端搜索框不用改。

### 3.1 顺带的权限收紧
- 谁都能建群 → 在 `CreateGroup` 前加策略（如仅主管及以上）；
- 谁都能拉人 → 群主/管理员才可邀请；
- 文件外发 → 前端禁用「保存到本地」+ 后端 MinIO 下载链接加短时效签名（现有 `/oss/` 直连，建议改成鉴权代理）。

## 4. 第四阶段：内部治理（合规必备）

| 需求 | 做法 | 落点 |
|---|---|---|
| **水印** | 全屏 SVG/CSS 水印，内容「姓名+工号+时间」，定时位移 | 前端 `openim-electron-enterprise` 根布局加一层 |
| **审计日志** | Gin 中间件记录 登录/建群/加人/删消息/文件下载 到 Mongo `audit_log` 集合 | `src/chat/internal/api/mw/` 新增 `Audit()`，在 `start.go` 挂到需要审计的组上 |
| **操作留痕查询** | 管理端加「审计日志」页，按人/时间/动作筛选 | `openim-admin` |
| **敏感词** | 发消息前拦截（前端提示 + 后端二次校验） | chat 的 `callback`/消息发送前钩子；也可用 OpenIM 的 `callback` 机制 |
| **消息导出** | 按会话/时间导出 Mongo 消息为 CSV/JSON，走审批 | 管理端加只读接口 |
| **强制下线** | 管理端踢人：置 token 黑名单（Redis）或改用户状态 | chat `admin` API 扩展 |

回调钩子已有现成入口：`src/chat/internal/api/chat/start.go:154` → `POST /callback/open_im`，
OpenIM 核心会在「发消息/建群/加好友」等事件回调到这里，适合挂审计与敏感词，**不用改核心**。

## 5. 前端二开的正确姿势（替换掉现在的「产物打补丁」）

```bash
# 1. 拿源码（不要用构建产物改）
git clone https://github.com/openimsdk/openim-electron-enterprise.git
cd openim-electron-enterprise
git checkout release-v3.8.3        # 与现网镜像版本对齐，避免 SDK 不兼容

# 2. 看 package.json 的 scripts，选 web 构建（该仓库同时出 electron 和 web）
npm i
npm run build:web                  # 具体脚本名以仓库 package.json 为准

# 3. 产物丢进自己的 nginx 镜像
#    Dockerfile:
#    FROM nginx:1.27-alpine
#    COPY dist /usr/share/nginx/html
#    COPY site.conf /etc/nginx/conf.d/default.conf
docker build -t registry.corp.com/xinbo/web:1.0.0 .
```

然后 `docker-compose.yaml` 里把 `OPENIM_WEB_FRONT_IMAGE` 指到自家镜像，`frontend-custom/` 那套
挂载覆盖就可以逐步删掉（只保留 nginx 反代配置）。

**改品牌的最小集合**：`src/i18n/zh-CN.json`、`index.html` 的 title、favicon/logo 资源目录、
主题色变量（CSS 变量文件）、`app.config` 里的版权字段——比现在二进制替换稳一万倍。

## 6. 后端二开的工程化流程

```bash
# 1. fork 到公司 GitLab，保留 upstream
git remote add upstream https://github.com/openimsdk/chat.git
git checkout -b corp/1.0

# 2. 改完自测接口
docker build -t registry.corp.com/xinbo/chat:1.0.0 src/chat
# 3. compose 里换镜像（只改 image 一行）
# 4. 升级官方时：git fetch upstream && git rebase upstream/main，冲突集中在你自己加的文件里
```

约定：
- 官方文件尽量「少改、小改」，新增功能尽量放新文件（`internal/api/chat/corp_*.go`），减少升级冲突；
- 所有改动记 `CHANGELOG-corp.md`，写清「为什么改、改了哪个文件、怎么回滚」；
- 镜像 tag 用日期+语义版本，别用 `latest`（回滚靠 tag）。

## 7. 不要干的事（踩过就知道疼）

1. **别 fork 大改 `open-im-server`**：gRPC 微服务 + Etcd 服务发现 + Kafka，升级一次要重放全部改动；优先用 config 和 callback。
2. **别动 Mongo 集合结构**：`openim_v3` 的 schema 由核心服务管理，加字段可能被下一次启动覆盖（真需要就建独立集合）。
3. **别再往构建产物里塞功能**：`frontend-custom/assets/*.js` 这种字符串替换，官方一升级文件 hash 就变，功能全丢。
4. **别把 MinIO / Mongo 端口暴露到公网**：现在 compose 里是 `127.0.0.1` 绑定，保持这样。
5. **别用默认 `OPENIM_SECRET` 上线**：等于所有人可伪造 token。
