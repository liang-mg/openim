# 仓库开发流程（团队协作唯一准则）

> 本仓库 `github.com/liang-mg/openim` 是团队开发的**唯一真相源**。所有人都在仓库里改代码、提交、拉取，不再有本机大仓与协作仓的双向同步。

## 一、核心原则

1. **仓库即源码**：`backend/`（Go 后端）、`frontend/`（React + Electron 前端）是唯一源码，改完直接 commit/push。
2. **拉取即运行**：任何人 clone 后 `bash deploy/deploy.sh bootstrap`，一条命令起后端（10010）+ OA 网页（5173）+ 管理后台（11002，新博品牌）。
3. **改代码必须重建镜像**：Go 和前端代码都编译进 Docker 镜像，只 `up` 不 `build` 跑的还是旧的。

## 二、开发者日常

### 首次加入

```bash
git clone https://github.com/liang-mg/openim.git && cd openim
bash deploy/deploy.sh bootstrap
# 打开 http://127.0.0.1:5173
```

- 后端走 Docker 镜像内编译，**本地不需要装 Go**
- 前端要装 Node 依赖：`cd frontend && corepack pnpm i`（回归脚本也依赖这里的 playwright）

### 改完代码交付给别人

```bash
cd openim
git pull --ff-only                    # ① 先拉，避免和同事分叉
# 改 backend/ 或 frontend/ 下的代码
git add -A && git commit -m "说明改了什么"
git push origin main                  # ② 推给同事
```

### 拉到别人的改动并运行

```bash
cd openim
git pull --ff-only
bash deploy/deploy.sh build           # ① 重建镜像（关键，不能省）
bash deploy/deploy.sh up              # ② 重启生效
bash deploy/deploy.sh verify          # ③ 健康检查
```

## 三、打包桌面端 exe

```bash
cd openim/frontend
corepack pnpm i                       # 首次
corepack pnpm typecheck
corepack pnpm build:win
# 产物：frontend/release/Base/<版本>/新博_<版本>.exe
```

- `build:win` 只能在 Windows 上打 .exe
- 后端地址在 `frontend/src/utils/serverConfig.ts` 的 `BUILTIN_SERVER_HOST` 内置，换服务器要改这里重新打包
- 详见 [桌面端部署与分发.md](桌面端部署与分发.md)

## 四、管理后台品牌（11002）

品牌覆盖文件在 `frontend-custom/admin/`，已纳入 `bootstrap` 自动挂载，改了强刷浏览器即生效（唯一热生效层）。官方 admin 镜像升级导致 `umi.*.js` hash 变化时，重跑 `node scripts/patch_brand_admin.js` 并同步改 `deploy/docker-compose.brand.yaml` 里的挂载文件名。

## 五、常用命令速查

```bash
bash deploy/deploy.sh bootstrap   # 首次一键部署（建 env、构建、启动、校验）
bash deploy/deploy.sh build       # 改代码后重建镜像
bash deploy/deploy.sh up          # 启动/重启服务
bash deploy/deploy.sh down        # 停止（不动数据卷）
bash deploy/deploy.sh verify      # 健康检查 + 品牌校验
bash deploy/deploy.sh logs        # 看日志
node scripts/oa_e2e_check.js      # 回归测试（需服务已启动）
```

## 六、常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| pull 了新代码但功能没变 | 只 `up` 没 `build`，跑的还是旧镜像 | `bash deploy/deploy.sh build && up` |
| 后台 logo 没更新 | 浏览器缓存旧图 | `Ctrl+F5` 强制刷新 |
| `git pull` 报分叉 | 本地有未推送提交 | 先 `git push`，或用 `git pull --rebase` |
| GitHub 拉不下来（502 / schannel） | 网络代理问题 | `git -c http.proxy=http://127.0.0.1:7897 pull`（Clash 混合端口） |
| 打包 exe 报缺依赖 | 没装 node_modules | `cd frontend && corepack pnpm i` |

## 七、关于 `src/` 大仓（已废弃）

早期团队在本机 `openim-docker-latest/` 大仓的 `src/` 目录开发，靠 `scripts/sync-frontend.mjs` 双向同步到仓库。这条路径**已废弃**：

- `src/` 不再作为工作副本，所有开发回到本仓库
- 官方 IM 底座（`open-im-server`、`chat`）的少量二开改动已存档在 [docs/patches/openim-official/](patches/openim-official/README.md)，不参与构建
- 若仍持有旧大仓副本，请勿从它同步覆盖本仓库——本仓库的业务代码与其一致，但部署配置（Dockerfile / nginx）以仓库版本为准
