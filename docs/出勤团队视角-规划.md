# 出勤团队视角与权限整体规划

> 版本：2026-11-19 · 状态：**已实施（批次 3.2）**，实施细节见 `docs/打卡功能-详细设计.md` 第十节
> 起因：出勤记录只有「本人」视角，组长看不到组员；而日报已经有组长/领导视角。两个模块的权限口径不一致，属于结构性问题，不能只给考勤单独打补丁。
>
> 落地与本文的差异（据实记录）：
> - 作息按用户确认的 **09:05 上班 / 18:00 下班**，做成了环境变量配置（`OA_WORK_ON_TIME` / `OA_WORK_OFF_TIME`），规则配置页仍未做（P1-1 剩余）。
> - `visibleUserIDs` 已统一，`teamIDs` 改为递归（四级组织不再断链）。
> - **H9 未修**：日报 `submitted → pending_leader` 的状态机要一起改，留到日报改造时做（本文第二节把它和 H6 归为同一根因，结论仍然成立）。
> - 报表落地为 CSV（带 BOM）而非 xlsx；按部门维度仍等 P2-1 部门树。

## 一、先回答：组长现在怎么看

**看不到。** 实测（2026-11-19，`/checkin/list?month=2026-11`）：

| 账号 | 角色 | 汇报关系 | 本月能查到的记录 |
|---|---|---|---|
| 李然 | 员工 | 上级=王强 | 24 条（自己） |
| 张明 | 员工 | 上级=王强 | 2 条（自己） |
| 王强 | 组长 | 上级=王经理 | 0 条（自己） |
| 王经理 | 领导 | 顶层 | 0 条（自己） |

原因很直接：`CheckinList` 的查询条件写死了 `user_id = 当前登录人`，没有 scope 参数，也没有任何"下属"逻辑。

而日报那边已经有：`subordinateIDs()`（直属下属）和 `teamIDs()`（下属 + 下属的下属），组长能看下属日报、领导能看团队日报。

**同一个系统里，日报按汇报链走，考勤按"只看自己"走**——这就是不整体的地方。再往后加请假、补卡、异常、审批中心，如果每个模块各自再发明一套"谁能看谁"，会越做越乱。

## 二、一条主线：组织关系只有一份，权限判定只看"关系"

### 2.1 三层结构，各管一件事

| 层 | 是什么 | 谁维护 | 现状 |
|---|---|---|---|
| 组织关系 | 谁向谁汇报（`oa_employee.manager_id` 单链） | 管理页加人/改直属上级 | 已有，防环已做 |
| 数据范围 | 我能看哪些人的数据（`mine` / `team` / `all`） | 服务端按组织关系实时算 | 只有日报有，考勤没有 |
| 功能权限 | 我能不能进这个页面/点这个按钮（角色） | 角色：employee / manager / leader / hr + `is_admin` | 已有 |

铁律：**功能权限决定"入口可见"，数据范围决定"看到谁"，数据范围永远由服务端算，前端传什么都不作数。**

### 2.2 统一成一个函数，四个模块共用

```
visibleUserIDs(ctx, uid, scope) → []string
  scope=mine  → [uid]
  scope=team  → 沿 manager_id 递归全部下属（visited 防环，排除 disabled）
  scope=all   → 全公司（仅 hr / is_admin）
```

调用方：

| 模块 | 现在 | 改成 |
|---|---|---|
| 日报审阅 | `subordinateIDs` / `teamIDs`（**只两层，深组织会断链**） | `visibleUserIDs(uid, "team")` 递归全链 |
| 考勤（本次） | 无 | 同上 |
| 工作台待办 | 用 `subordinateIDs` 算待点评数 | 同上，口径与列表一致 |
| 审批中心（后续） | 未做 | 同上 |

**顺带修掉两个存量缺陷**：

- `teamIDs` 只取两层。现在正好三层能覆盖，一旦出现"组长→主管→经理→总监"四级，王经理就看不到第 3 层以下的人。改递归后一次解决。
- H9：组长自己的日报没人审，根因是 `review-list?view=manager` **按角色判**（要求 role=manager），而组长的上级是 leader。改成**按关系判**（"你是不是这个人的直属上级"），H9 自动消失，且不会因为角色调整而再次越权。

> 一句话：**把"你是不是他的上级"这件事做成一个判断，日报/考勤/待办/审批都用它，而不是每个模块各写一遍角色 if。**

## 三、谁能看谁（数据视角矩阵）

| 视角 | 触发条件 | 可见范围 | 用途 |
|---|---|---|---|
| 本人 | 所有人 | 自己 | 打卡、看自己月历（已实现） |
| 组长 | `role=manager`，或"我名下有下属" | 递归全部下属 | 看组员今天来没来、本月异常 |
| 领导 | `role=leader` | 递归全部下属（含跨级） | 看整条线 |
| HR | `role=hr` | 全公司，可按部门筛 | 考勤核对、导出 |
| 管理员 | `is_admin` | 全公司 + 组织维护 | 同上 + 管理页 |

注意两点：

1. **不按 `department` 字符串分组**。现在部门是自由文本（"技术部"/"技术部 "/"研发部" 都可能出现），按它聚合必然错。部门维度等 P2-1 部门树（`oa_department` + `department_id`）落地后再加，接口先留 `group_by=department` 的位置。
2. **停用/离职**：不出现在团队列表与"应到人数"里，历史记录保留（月报导出时标"已离职"）。

## 四、页面怎么呈现（出勤页加"我的 / 团队"）

`#/attendance` 顶部加视图切换，只有 `mine/team` 权限的人能看到"团队"这一档。

### 4.1 团队视图（组长默认落地页）

```
┌ 出勤记录 ─────────────────────────────── [我的] [团队]  2026 年 11 月 ◀ ▶ ┐
│ 应到 2 人 · 已打卡 1 · 未打卡 1 · 迟到 1 · 缺卡 3        [只看异常]        │
├──────────────────────────────────────────────────────────────────────────┤
│ 成员          今日上班      今日下班      本月出勤 迟到 早退 缺卡  操作    │
│ 李然 技术部   08:48 正常    未打 ⚠       13 天   1    1    1   查看月历 → │
│ 张明 技术部   未打卡 ⚠      —            4 天    0    0   10   查看月历 → │
└──────────────────────────────────────────────────────────────────────────┘
```

- **默认按"异常优先"排序**：未打卡 → 迟到/早退 → 正常，组长一眼看到问题人，不用逐行找。
- **今日状态不是月历**：组长日常关心的是"今天谁没来"，月历是点进去才看的详情。
- 点「查看月历 →」展开该成员的个人月历（复用现有日历组件，**只读**，不能改别人的卡）。
- 「只看异常」一个开关，过滤掉正常的人。
- 领导/HR/管理员多一个范围切换：`我的团队` / `全公司`（仅 hr、admin）。

### 4.2 空态与边界

| 场景 | 表现 |
|---|---|
| 组里一个人都没有 | "你名下暂无成员，去管理页设置直属关系"（管理员看到的是"去添加成员"链接） |
| 越权访问别人的月历 | 服务端 403「无权查看该成员考勤」，页面提示并退回列表 |
| 停用成员 | 不出现在列表；直接访问其月历返回 403 |

## 五、统计口径（这一节决定组长信不信这些数字）

现有本人月历的口径基本可用，但搬到团队视角会放大三个问题，必须一起修：

| # | 口径 | 现状 | 团队视图要求 |
|---|---|---|---|
| 1 | **今天还没下班，不算缺卡** | 只打上班卡就返回"缺一次卡"（今天 16:30 也这么显示） | 当天且未到下班时间 → 状态"进行中"，不计缺卡、不标红。本人视图一并修 |
| 2 | **请假未接入前，缺卡可能是假的** | 缺卡 = 当天没记录，请假/出差的人会被算成缺卡 | 列表页与汇总处明确标注「暂不含请假/出差」，P1-2 落地后自动消失。**在请假上线前，不给"缺卡"做任何处罚性结论** |
| 3 | 迟到/早退时间写死 | `todayRule()` 固定 07:00/09:30/18:00（H3） | 团队视图上线前先做 P1-1 全局可配规则，否则组长看到的迟到判定不可信 |
| 4 | 工作日 | 只判周末，无法定节假日 | 先按"周一至周五"，节假日日历列入 P1-1 规则（可配置补班/放假） |
| 5 | 出勤天数 | 有上班卡即计 1 天 | 保持；请假通过后应显示"出勤 12 天 + 请假 1 天" |
| 6 | 补卡 | 未做 | 补卡通过后按 `source=makeup` 计入出勤，并在格子加"补"角标 |
| 7 | 范围外打卡 | 有 `fence_set/in_fence/distance` | 表格里"范围外"只做提示，不作为异常结论（外勤场景会误判） |
| 8 | 跨天班次 | 不支持 | 明确不做，夜班需要"班次"模型，属于二期 |

> 结论：**团队出勤的可信度 = 规则可配 + 请假接入 + 今天未下班不算缺卡**。第 1 条本次必须做，第 3 条建议本次一起做，第 2 条要如实告诉用户"还差请假"。

## 六、接口契约（服务端判权，前端只渲染）

### 6.1 团队列表

```http
GET /oa/api/v1/checkin/team?month=2026-11&date=2026-11-19&scope=team&only_exception=0
token: <chatToken>
```

```json
{
  "code": 0,
  "data": {
    "scope": "team",
    "month": "2026-11",
    "date": "2026-11-19",
    "warnings": ["leave_not_integrated"],
    "summary": { "members": 2, "present": 1, "absent": 1, "late": 1, "early": 0, "missed": 0 },
    "members": [
      {
        "user_id": "2158780278",
        "name": "李然",
        "department": "技术部",
        "position": "工程师",
        "role": "employee",
        "today": {
          "state": "partial",
          "on": { "time": "08:48", "status": "normal", "status_text": "正常", "place": "22.54080, 113.93470", "photo": true },
          "off": null
        },
        "month": { "attend": 13, "late": 1, "early": 1, "absent": 1, "missed": 0 },
        "last": { "time": "08:48", "place": "22.54080, 113.93470" }
      }
    ]
  }
}
```

- `only_exception=1` 时只返回今天异常的人（未打卡/迟到/早退/缺卡），用于「只看异常」开关。
- `warnings` 明确把"请假未接入"透传给前端，避免前端自己写死提示。
- 越权：`scope=team` 但角色不够 → `403 {"code":403,"msg":"无权查看团队考勤"}`；不是空列表。

### 6.2 成员月历

```http
GET /oa/api/v1/checkin/team/:user_id?month=2026-11
```

返回结构与本人 `/checkin/list` 一致（多 `user` 节点），前端复用同一个日历组件。

校验顺序：① 目标 user 是否在本人的可见范围内 → 不在则 403；② 目标是否已停用 → 停用仍可查历史（给 HR），组长查停用返回 403。

### 6.3 性能与索引

- 一次查 `company_id + user_id in [...] + date >= 月初 && < 下月初`，内存聚合。
- 现有索引 `(company_id, user_id, date, type)` 可用；把 `date: {$regex: "^2026-11"}` 改成范围查询（`$gte/$lt`），让索引真正走到区间。本人接口一并改。
- 50 人 × 2 次 × 31 天 ≈ 3100 条，单次几十毫秒；超过 200 人再加"只查汇总/分页"。

## 七、落地顺序（对现有批次的调整建议）

原来 P1-4「考勤汇总」排在批次 5，且依赖请假/补卡。但**组长看不到组员这件事是硬缺口**，不该等三个批次。建议拆成两半：

| 批次 | 内容 | 状态 | 说明 |
|---|---|---|---|
| 3.1 | P1-1 考勤规则（全局一套可配：上下班时间、迟到宽限、工作日、是否需拍照/定位、围栏） | 待做 | 团队视图的可信度前提 |
| 3.2 | 团队出勤只读视图（统一 `visibleUserIDs` + `/checkin/team` 两个接口 + 出勤页"我的/团队" + 成员月历 + 顺带修 H9） | 待做 | 不含导出、不含异常单、不含请假扣减 |
| 4 | 请假 + 补卡（P1-2 / P1-3） | 待做 | 落地后团队视图的"缺卡"才真实 |
| 5 | 考勤汇总导出 + 异常扫描 + 待办（P1-4 后半 / P1-5 / P1-6） | 待做 | 导出 Excel、异常申诉 |
| 6 | 审批中心 + IM 推送 + 催交 | 待做 | — |
| 后续 | 部门树（P2-1）落地后，团队视图加"按部门"维度 | — | 接口已留 `group_by` 位置 |

如果只能做一半，**先做 3.2**（组长立刻能用），规则用当前写死的值，并在页面标注"作息按 09:30/18:00 判定"。
