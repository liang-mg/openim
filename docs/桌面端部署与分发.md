# 桌面端部署与分发

> Windows（NSIS 安装包）和 macOS（dmg）桌面应用，功能与 Web 端完全一致：OA 全部模块 + 聊天 + 账号密码登录。

## 一、同事怎么用（3 步）

1. 拿到安装包：Windows 用 `新搏_3.8.3.exe`，macOS 用 `新搏_3.8.3_x64.dmg`（Apple 芯片用 `_arm64.dmg`）。应用名、图标、快捷方式均为「新搏」。
2. 双击安装，一路下一步；macOS 若提示"无法验证开发者"，右键 → 打开 → 确认。
   - **Windows SmartScreen 拦截**：安装包未做代码签名，首次运行可能弹出蓝色提示"Windows 已保护你的电脑"。点"更多信息" → "仍要运行"即可。要彻底去掉此提示需购买代码签名证书。
3. 打开应用，在登录页填：
   - **服务器地址**：`oa.company.com`（只填域名或 IP，不要带 `http://`，程序自动拼端口）
   - **账号**：手机号，如 `12345678001`
   - **密码**：统一测试密码 `Xinbo@2026`

填一次服务器地址会记住，下次打开自动带出。换服务器时重新填即可，旧登录态会自动清除。

## 二、服务器地址怎么填

| 部署方式 | 填写示例 | 说明 |
|---|---|---|
| 标准部署（推荐） | `oa.company.com` 或 `10.0.0.5` | 程序自动连 10001/10002/10008/10010/10005/7880 端口 |
| 指定端口 | `oa.company.com:8080` | 各服务端口统一改成这个端口 |
| HTTPS 反向代理 | `https://oa.company.com` | 走 443 的同名路径 `/api`、`/chat`、`/oa` 等 |

不确定怎么填时，问部署同事"Web 版访问的域名是什么"，填那个域名即可。

## 三、开发者怎么打包

前置条件：Node 22+、pnpm（通过 `corepack pnpm` 使用）、已安装依赖。

```bash
cd src/openim-electron-demo

# 1. 类型检查（务必先过）
corepack pnpm typecheck

# 2. 检查打包配置（dry-run，不产出文件）
corepack pnpm electron:package:check

# 3. 打 Windows 安装包（产出到 release/Base/3.8.3/）
corepack pnpm build:win

# 4. 打 macOS 安装包（必须在 macOS 机器上执行，Windows/Linux 不支持交叉编译）
npx vite build
node scripts/electron-build.mjs --skip-build --mac --x64     # Intel 芯片
node scripts/electron-build.mjs --skip-build --mac --arm64   # Apple 芯片
```

> **平台限制**：electron-builder 只允许在对应系统上打安装包——Windows 上打 `.exe`，macOS 上打 `.dmg`，无法在 Windows 上生成 macOS 包（会报 `Build for macOS is supported only on macOS`）。要出 Mac 包，需在 Mac 机器上跑上面的命令，或配 GitHub Actions / CI 的 mac runner。

打包脚本 `scripts/electron-build.mjs` 会自动：构建 → 分析运行时依赖（**含传递依赖**，如 `i18next` 依赖的 `@babel/runtime`）→ 补 pnpm 顶层依赖链接（koffi/rxjs 原生库、`@babel/runtime`）→ 生成精简 package.json → 调 electron-builder → 还原 package.json。输出在 `release/Base/<版本>/`。

> **两个已修的坑**：
> 1. 精简 manifest 早期只收录直接依赖，导致 `i18next` 启动报 `Cannot find module '@babel/runtime/helpers/typeof'`。现已把整个运行时依赖闭包连同版本一起写入。
> 2. `vite.config.ts` 早期在配置加载阶段 `rmSync("dist-electron")`，沙箱会把它包装成回收站操作、文件多时超时。需要全新构建时，先在 shell 里 `rm -rf dist-electron` 再跑 `npx vite build`。

**图标来源**：`docs/brand/logo-xinbo.png`（512×512）→ 用 PIL 转成多尺寸 `ico`（Windows）、`mac_icon.png`（macOS）、`icon.png`（Linux/Tray），分别放在 `public/icons/`，vite 构建时拷入 `dist/icons/`。

**品牌配置**：`electron-builder.json5` 的 `productName`/`appId`/`shortcutName` 和 `electron/main/windowManage.ts` 的窗口标题均为「新搏」；`package.json` 的 `name` 保留 `OpenCorp-Base`（改动会影响 pnpm lockfile，产品名由 `productName` 控制，无需改）。

常用参数：
- `--skip-build`：复用已构建的 `dist` / `dist-electron`，只做打包（推荐，避免重复构建）。
- `--win --x64` / `--mac --arm64`：指定平台和架构。
- `--dry-run`：只打印将执行的命令，不产出文件。

## 四、技术实现要点

- **地址配置**：登录页填的 host 存 `localStorage.OA_SERVER_HOST`，由 `src/utils/serverConfig.ts` 的 `resolveServerURLs()` 统一派生 6 个服务地址。Web 端和 Electron dev 模式走同源相对路径，行为与改造前完全一致。
- **为什么不用主进程代理**：窗口 `webPreferences.webSecurity = false`，渲染进程可直接跨域请求，不需要 IPC 转发。
- **IM SDK**：`platformID` 用 `getPlatform()`（Windows=2 / macOS=3），与 Web 的 5 不同，同一账号可 Web + 桌面端同时在线不互踢。
- **切服务器一致性**：`setServerHost()` 发现 host 变化会清空 token，防止拿 A 服务器的 token 访问 B 服务器。
- **回归脚本**：`node scripts/oa_desktop_config_check.js` 验证地址派生规则（27 条用例）。

## 五、已知限制

1. **测试密码共用**：`Xinbo@2026` 是 6 个测试账号共用密码，正式使用前必须逐个改（密码归 IM 管，在 OpenIM 后台 `11002` 改）。
2. **macOS 未签名**：打出的 dmg 没做 Apple 签名/公证，首次打开需右键 → 打开。要免警告需加开发者账号签名。
3. **不做自动更新**：当前走手动分发，新版本需重新发安装包；接入 electron-updater 需要更新服务器。
4. **安装包较大**：含 IM native SDK 和 wasm，约 150MB+，首次分发建议用网盘。
