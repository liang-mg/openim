# 桌面端 · 运行时服务器地址配置设计

> 目标：把现有 `src/openim-electron-demo` 打成 Windows / macOS 桌面应用，同事安装后只需在登录页填一个服务器域名/IP，即可连接后端全部服务。Web 端行为完全不受影响。

## 一、现状与问题

Web 端所有地址都是"同源相对路径"，靠 `vite.web.config.ts` / nginx 反代到后端：

```
VITE_WS_URL  = /msg_gateway  → ws://127.0.0.1:10001
VITE_API_URL = /api          → http://127.0.0.1:10002
VITE_CHAT_URL= /chat         → http://127.0.0.1:10008
/oa                          → http://127.0.0.1:10010
/oss                         → http://127.0.0.1:10005
/livekit                     → ws://127.0.0.1:7880
```

Electron 生产模式是 `mainWindow.loadFile(index.html)`，`window.location.origin` 是 `file://`，上面所有相对路径全部失效。

好消息：主进程 `webPreferences.webSecurity = false`，渲染进程可以直接跨域请求任意地址，**不需要主进程代理**，只需把地址换成完整 URL。

## 二、地址派生规则（唯一实现）

同事在登录页只填一个 host，例如 `oa.company.com`。`resolveServerURLs(host)` 派生：

| 服务 | 标准端口模式（默认） | 反向代理模式（host 带 `https://`） |
|---|---|---|
| IM API | `http://host:10002` | `https://host/api` |
| 消息 WS | `ws://host:10001` | `wss://host/msg_gateway` |
| Chat API | `http://host:10008` | `https://host/chat` |
| OA API | `http://host:10010` | `https://host/oa/api/v1` |
| 文件 OSS | `http://host:10005` | `https://host/oss` |
| LiveKit | `ws://host:7880` | `wss://host/livekit` |

模式判定：用户填的值带 `https://` 前缀 → 反向代理模式；否则 → 标准端口模式。带 `http://` 前缀时剥掉前缀后按标准端口模式处理。这样同事两种部署方式都能用，且不用填六次。

输入归一化：去首尾空格、去末尾 `/`、去协议头（https 除外，用于判定模式）、允许 `host:port`（此时端口覆盖默认端口，仅标准模式）。

## 三、配置存哪、何时生效

- 存储：`localStorage.OA_SERVER_HOST`，只存用户原始输入字符串。
- 读取：`getServerHost()` 同步读；`resolveServerURLs()` 每次调用时实时派生（不缓存完整 URL，避免改配置后旧 URL 残留）。
- 写入：登录页 `onFinish` 前先 `setServerHost(host)`，再发登录请求；登录成功后所有 API 实例和 SDK 都用新地址。
- 生效时机：**登录时生效**。已登录状态下不能改配置（登录页进不去），要换服务器先退出登录。
- 与 token 一致性：`setServerHost()` 若发现 host 变化，调用 `clearIMProfile()` 清空旧 token，防止串服务器鉴权。

## 四、Web 端兼容（不能破坏现有 5173 和公网隧道）

Web 浏览器里 `window.electronAPI` 不存在。此时**完全走现有逻辑**：

- `resolveServerURLs()` 检测非 Electron 环境，返回基于 `window.location.origin` 的同源路径（`/api`、`/chat`、`/oa/api/v1`、`/msg_gateway`、`/oss`、`/livekit`）；
- 登录页不显示"服务器地址"输入框（Web 部署时地址由域名决定，用户不该改）；
- Electron dev 模式（`VITE_DEV_SERVER_URL` 存在）也强制走同源路径，因为 vite dev server 有代理，避免开发时还要填地址。

判定函数统一为 `isElectronRuntime()`：`!!window.electronAPI && !import.meta.env.VITE_DEV_SERVER_URL`。

| `src/layout/useGlobalEvents.tsx` | SDK `apiAddr` / `wsAddr` 改为 `resolveServerURLs()`，Electron 用完整 URL，Web 用同源 |

为什么不用 electron-store + IPC：配置是渲染进程自己用的，主进程不需要读；用 localStorage 与现有 token 存储方式一致，改动面最小，也不会因为 IPC 时序导致首次登录读不到配置。

## 六、数据一致性与安全边界

- 配置不含密码、不含 token，只有域名/IP，明文存 localStorage 无敏感风险。
- 切换服务器后强制清空 token：这是唯一的状态机转换点，集中在 `setServerHost()`，不在登录页散落判断。
- 地址派生失败（host 为空/非法）时回退到 Web 同源逻辑，保证页面不会白屏；Electron 下若未填 host 则登录页校验阻止提交。
- IM SDK 的 `platformID`：桌面端继续用 `getPlatform()`（Windows=2 / macOS=3 / Linux=4），与 Web 的 5 不同。同一账号可同时在 Web 和桌面端在线，不会被互踢。
